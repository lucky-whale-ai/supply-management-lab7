# Поставка товаров

Учёт товаров, заказов и отгрузок завода «Прогресс». ЛР №7, вариант 1.
Приложение находится в ветке `lab7`.

## Запуск

Нужны Node.js 22+ и PostgreSQL. Создай базу `progress_lab7` через pgAdmin
или SQL-командой `CREATE DATABASE progress_lab7;`.

Параметры подключения хранятся в `.env`. Для новой копии проекта скопируй
`.env.example` в `.env` и укажи своего пользователя и пароль PostgreSQL.
Готовый локальный `.env` заменять не нужно; в Git он не добавляется.

```powershell
npm install
npm run db:seed
npm run build
npm start
```

Открыть **http://127.0.0.1:3007**. Остановка сервера — `Ctrl+C`.
После изменений JSX нужно повторить `npm run build`. Для разработки можно
отдельно запустить `npm run dev:client` и открыть порт 3000 при работающем API.

## Устройство

```text
server/database.js     подключение Sequelize к PostgreSQL
server/models.js       четыре модели, связи и проверки значений
server/routes.js       CRUD и проверка существования записей
server/query.js        пагинация, сортировка, фильтры и поиск
server/seed.js         начальное заполнение базы
client/store/          данные и запросы Redux
client/pages/          списки, формы и подробный просмотр
client/entities.js     поля и подписи четырёх разделов
public/styles/         общие стили, расположение блоков, компоненты
postman/               коллекция запросов
```

В заказе указан один товар. Отгрузка состоит из позиций; каждая позиция
ссылается на заказ и содержит фактическое количество. Поэтому одна отгрузка
может включать несколько товаров, а заказ — выполняться частями.

| Таблица | Основные данные |
|---|---|
| `products` | Название, цена в тыс. руб., фотография, описание |
| `orders` | Заказчик, адрес, телефон, договор, товар, плановое количество |
| `shipments` | Номер, дата, примечание |
| `shipment_items` | Отгрузка, заказ, фактическое количество |

Функция заполнения создаёт 60 записей: 10 товаров, 15 заказов, 10 отгрузок
и 25 позиций. Если в базе уже есть данные, повторное заполнение пропускается.
Связанные записи защищены от удаления: сначала нужно удалить зависимые позиции
и заказы. Клиент запрашивает подтверждение и показывает причину отказа сервера.

## API и Postman

Ресурсы: `/api/products`, `/api/orders`, `/api/shipments`, `/api/shipment-items`.
Для каждого используются одинаковые операции:

| Запрос | Результат |
|---|---|
| `GET /api/ресурс` | Список и сведения о пагинации |
| `GET /api/ресурс/:id` | Подробная запись или `404` |
| `GET /api/ресурс/:id/exists` | `{ "exists": true/false }` |
| `POST /api/ресурс` | Создание, `201` |
| `PUT /api/ресурс/:id` | Изменение всей записи, `200` |
| `DELETE /api/ресурс/:id` | Удаление, `204`; при наличии связей — `409` |

Общие параметры списка: `page`, `pageSize` (до 100), `sort`, `order`, `q`.
`q` ищет текст сразу в нескольких полях; фильтры применяются совместно.

| Ресурс | Фильтры |
|---|---|
| Товары | `name`, `minPrice`, `maxPrice` |
| Заказы | `productId`, `customerName`, `dateFrom`, `dateTo` |
| Отгрузки | `number`, `dateFrom`, `dateTo` |
| Позиции | `shipmentId`, `orderId`, `minQuantity`, `maxQuantity` |

Пример: `/api/products?page=1&pageSize=5&sort=price&order=desc`.
POST и PUT принимают JSON. Ошибки возвращаются как `{ "error": "сообщение" }`.

Импортируй `postman/progress.postman_collection.json` в Postman. Переменная
`baseUrl` по умолчанию равна `http://127.0.0.1:3007`. При работающем сервере
запусти всю коллекцию через Runner: её запросы зависят от предыдущих.

Сценарии коллекции:

1. Для каждого ресурса получить список с пагинацией, проверить отсутствующий
   и неверный ID, запросить существование записи.
2. Создать товар, заказ, отгрузку и позицию; получить их по ID и изменить.
3. Проверить сортировку, поиск по основным и связанным полям, несколько фильтров.
4. Отправить пустое название, отрицательную цену, неверный телефон, несуществующую
   дату, нулевое количество и ссылку на отсутствующую запись. Ожидается `400` или `409`.
5. Проверить повтор номера отгрузки и позиции, запрет удаления связанных записей.
   Ожидается `409`; неправильные параметры списка дают `400`.
6. Удалить созданные записи в обратном порядке связей и убедиться, что товара
   больше нет. Исходные записи коллекция не удаляет.

Коллекция выполнена через Postman CLI: 60 запросов, 112 проверок, ошибок нет.
